# Round 20 — SIM Subsystem Divergence Mapped (modem-ver-20)

## Goal
Instrument/find where our V24's USIM init parks (DETECTED → READY).

## Transport doors: all closed (confirmed exhaustively)
- /dev/atci1 (atcid owns it, no line discipline)
- /dev/pts/* (muxd PTYs, no responses on idle channels)
- /dev/ccci_monitor, /dev/ccci_it, /proc/ccci_log (empty/hang)
- /dev/ttyC0..C3: **ttyC0 = fd0 of RIL (pid holds it), ttyC2 busy, ttyC3 no reply**
- mdlogger/emdlogger1: runs, writes nothing
=> No direct AT/console access exists on this 2015 HTC userland.

## The real finding: our SIM library is an OLDER MTK drop than stock's
String-diff of the SIM subsystem (ours vs stock) shows stock contains
code ours simply does not have:
- `[SIM Q] ...` instrumentation family (init/find/pop/put queue tracing)
- `SIM_CMD:WrongReqLen` / `WrongRspLen` validation
- `SIM Hot Plug Out during APDU REQ and RSP` recovery
- `SIM no inserted & retry sim by recovery`
- `SIMcardError & retry sim by recovery`
- `Test SIM inserted`
- `sim_stop_timer() but return out`
- HTCDBG.FN sim_* debug family
- HTC signal-bar-filter code (Reset signal bar filter parameters...)

And the build-config smoking gun:
- stock compiled `custom/driver/drv/misc_drv/MT6795_HIAU/DEFAULT/custom_sim_driver.c`
  (HTC board = "HIAU", HTC-In-Amsterdam-UT?; M9 family)
- ours compiled `_Default_BB/MT6795/custom_sim_driver.c` (generic)
- our tree HAS NO MT6795_HIAU directory at all

## Structural facts established
- modem/sim in our tree = headers only; SIM task ships as prebuilt
  mtk_rel/.../lib/libsim.a (94 libs total in mtk_rel; ours has 387 T syms)
- Stock image is fully stripped (no .symtab) → binary diff must use
  string anchors (same method as the GGE/UMTS transplants)
- The ICCID/APDU path works via RIL; NVDATA not churning (no recovery
  loop writing NVRAM); no CCCI errors

## Interpretation (working theory, evidence-based)
Our generic+older SIM stack most likely parks in a case HTC's newer
lib handles (e.g. hot-plug-during-APDU, recovery-on-card-error, or a
queue-wait whose counterpart message never arrives). The visible
symptoms fit: APPSTATE_DETECTED forever, 0x91 0x34 proactive-pending
never FETCHed (SAT session start = early victim of a wedged queue).

## Next round plan (ver-21): binary SIM transplant
1. Extract stock's sim code region via string anchors ([SIM Q] cluster
   0x787d00-0x789000, sim lib strings; find function boundaries by
   prologue scanning around anchor references)
2. Locate our equivalent region in the built bin
3. Transplant stock's SIM objects (or whole .text segment slices) into
   our image; fix up literal pools/BL targets; keep our RF port intact
4. Diag boot (asserts live) → if init proceeds past DETECTED, we've
   found it; if it asserts, the assert names the exact missing piece
   (stock's recovery code paths will now exist to catch it)

Alternative (bigger hammer): whole-section replace of the SIM task
code+data from stock with address-map reconciliation.
