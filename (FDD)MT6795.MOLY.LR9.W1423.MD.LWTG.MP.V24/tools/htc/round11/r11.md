# Round 11 — TDD Table Fix + Layer-3 Discovery (modem-ver-16)

## What was found and fixed
1. **TDD TX-table port bug (mine, R8b)**: B39/B40 TX rows were sourced
   from RX-shaped clusters (TDD bands share ARFCNs; naive anchor matched
   RX). Correct PA-row clusters: B38@0x8a3cc8, B39@0x8aa75c, B40@0x8ac73c.
   Source-fixed, committed, rebuilt.
2. **Build-order bug (mine)**: first r11 flash used a stale bin (the
   rebuild hadn't picked up the patch; md5 differed). Forced rebuild
   (touch) produced correct bin; verified TDD rows byte-exact in-bin.
3. **GGE relocation handling**: rebuild shifted addresses; GGE cluster
   re-anchored by signature-scan (0x848e2c/0x84a88c/0x84dd0c/0x84f774).

## Decisive finding (r11b-diag, asserts live, NVRAM clean)
**ephy:171 para(1,5,0) STILL fires.** Disassembly of the checker caller
(this round, new ELF) shows it validates via pointer arrays
(LTE_MIPI_RX/TX_DATA_TABLE[], lteBandIndArray) — and those compiled
tables now carry correct HTC rows (verified byte-exact in-bin). Yet the
check fails at idx5.

a band-idx-5 table whose freq edges mismatch the compiled reference.
