# Round 46 — Bars Blocker Root Cause: 2G/UMTS MIPI Tables Never Source-Ported (modem-ver-46)

## Chain of evidence this round
1. nvram_init_uL1_mipiTxEvent RUNS (probe LR nvram_init_uL1_mipiData+0x65)
   - UL1 (2G) MIPI tables are NVRAM-fed; NVD_DATA has NO UL1 files
     (only EL1A etc.) -> reads fail -> MOLY defaults used
2. GGE runtime tables = .bss composites filled from l1d_custom_mipi.c
3. git archaeology: R5 'GGE+LTE+UMTS transplant' was BINARY-only
   (image patches, lost in R39 source rebuild — same failure class
   as the ephy nops we re-applied, but GGE was never redone)
4. LTE got source ports (R12, el1_rf lte_custom_mipi.c commits);
   2G (l1_rf) + UMTS (ul1_rf) sources are byte-identical to
   mtk-source modulo line endings = STILL MOLY GENERIC
5. Iran (IR-MCI) = GSM900/1800 network -> first real band config is
   2G -> DSP validates MOLY-generic GGE event tables vs HTC RF
   hardware -> RFD_MIPIevent.c:134 @FMC assert -> MD reset -> no bars

## Why LTE-only porting wasn't enough
Network search configures GSM first (or the DSP validates all RAT
tables at init); MOLY-generic 2G tables fail HTC validation.

## Fix plan (ver-47): GGE source port
1. Extract stock GGE tables from stock image (binary struct parse,
   anchored by our ELF's GGE_MIPI_CTRL_TABLE_* layout - same build
   family, structs compatible)
2. Emit C arrays (R12 gen_r12.py method) into l1d_custom_mipi.c
3. Same for UMTS (ul1d_custom_mipi.c) if needed
4. Rebuild + full nop re-application + flash
