## Airtight chain of evidence (R23→R33)
PHB issues SIM_READ_REQ (R28 probe: phb_issue_IO_read RUNS)
SIM entity starts its own USIM reads (R23: usim_read_* RUNS, ICCID
  even completes — framework saw it)
SIM entity NEVER sends a read confirmation to ANY requester:
  - PHB: phb_IO_sim_read_cnf silent
  - L4/protocol: sim_read_cnf_hdlr silent
  - security exchange never confirms (R26)
  - PHB retries 4x (EIND:32 x4) then stops
=> The prebuilt SIM library's async read-completion path is broken
in our build. Requests accepted, responses never dispatched.

## Why this is THE root cause
Every symptom since R18 maps to it:
  APPSTATE_DETECTED forever / no IMSI to L4C / no security cnf /
  PHB error loops / no +EIND:2 / RIL waiting forever.
Stock's HTC-patched [SIM Q] queue instrumentation sits exactly in
the SIM task's message queue (find/pop/put) — consistent with HTC
patching this very completion/dispatch path.
