PHB startup → issue_IO_read → SIM READ_REQs → cnf comes back to

+EIND:32 retries = phb_startup_confirm loops). The final
`bl l4c_phb_startup_finish_rind` at 0x3EA004 sits behind:
  [cnf+4]==1 (result success) AND [l4c_ctx+0x54]!=0x68 AND [+0x531]==0

## Refined root-cause chain (updated)
SIM entity completes its own init (R24) but its FILE-READ service
for other tasks (PHB ADN reads; earlier: security exchange) returns
failures. Note l4cphb_startup_read_ind_hdlr silent while
issue_IO_read runs: PHB reads via NVRAM path first (ME phonebook in
NVRAM/FS) — those work — then ADN from SIM fails.
=> The SIM entity's file-read CONFIRMATIONS carry error status.
Hypothesis: the SIM task's USIM read path rejects because the ADF/USIM
app session isn't fully activated for file access (matches the
ISIM/USIM app activation nuance from R18: session opened for ICCID
reads — which worked — but not for ADF-hosted files like ADN).
